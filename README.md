# 🛰️ Tech Radar Agent

A serverless, event-driven research pipeline built on **Azure Durable Functions**. It takes a research topic, searches the web, pauses for human approval on the sources, scrapes the approved pages in parallel, and synthesizes a Markdown report using Azure AI.

## 🚀 Features
- **Human-in-the-Loop (HITL):** The workflow pauses and waits for the user to approve the search results before spending AI tokens.
- **Fan-Out / Fan-In:** Scrapes multiple approved URLs in parallel to reduce processing time.
- **Serverless & Resilient:** Built on Durable Functions, meaning the workflow state is persisted. If the server crashes while waiting for approval, it resumes exactly where it left off.
- **Interactive UI:** Includes a lightweight Vanilla JS dashboard to start research and approve sources.
- **Automated CI/CD:** Deploys automatically to Azure via GitHub Actions using OIDC (passwordless) authentication.

## 🏗️ Architecture & Design Decisions
This project was built to explore **Orchestrated AI Workflows. 

1. **Why Durable Functions?** Standard HTTP functions time out. The workflow needs to pause for potentially 10 minutes while a human reviews the URLs. Durable Functions allow the compute to scale to zero while waiting, and resume only when an external event (approval) occurs.
2. **Deterministic Orchestration:** The Orchestrator function contains no I/O. All network calls (Search, Scrape, AI) are pushed to Activity functions so the Durable engine can safely replay the workflow history.
3. **Resilient Search:** The search activity includes a circuit breaker. If DuckDuckGo times out or rate-limits the request, it automatically backs off and falls back to a secondary search provider.

## 🛠️ Tech Stack
- **Compute:** Azure Functions (Python 3.13, v2 model, Flex Consumption)
- **Orchestration:** Azure Durable Functions
- **AI:** Azure AI Foundry
- **Storage:** Azure Blob Storage (for saving the final Markdown report)
- **Search:** DuckDuckGo Search (`ddgs`)

## 🔌 API Endpoints
While the UI (`/api/dashboard`) is the primary way to interact, the backend exposes:
- `POST /api/research`: Starts the orchestration.
- `GET /api/dashboard`: Serves the single-page application.

*(The approval step is handled via the `sendEventPostUri` dynamically generated by the Durable engine).*

## 💻 Running Locally

### Prerequisites
- Python 3.13
- [Azure Functions Core Tools](https://learn.microsoft.com/en-us/azure/azure-functions/functions-run-local) (v4)
- [Azurite](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azurite) (Storage Emulator)
- Docker (for the Durable Task Scheduler emulator)
- An Azure AI Foundry resource

### Setup
1. Clone the repository:
   ```bash
   git clone https://github.com/CubongJay/Tech-Radar-Agent
   cd tech-radar-agent
   ```

2. Install dependencies (using `uv`):
   ```bash
   uv sync
   ```

3. Start the local Durable Task Scheduler emulator:
   ```bash
   docker run -itP mcr.microsoft.com/dts/dts-emulator:latest
   ```

4. Create a `local.settings.json` file:
   ```json
   {
     "IsEncrypted": false,
     "Values": {
       "AzureWebJobsStorage": "UseDevelopmentStorage=true",
       "FUNCTIONS_WORKER_RUNTIME": "python",
       "DURABLE_TASK_SCHEDULER_CONNECTION_STRING": "Endpoint=http://localhost:8080;TaskHub=default;Authentication=None",
       "AZURE_OPENAI_ENDPOINT": "https://your-resource.services.ai.azure.com/models",
       "AZURE_OPENAI_KEY": "your-key",
       "AZURE_OPENAI_DEPLOYMENT": "gpt-4.1-mini",
       "BLOB_CONNECTION_STRING": "UseDevelopmentStorage=true"
     }
   }
   ```

5. Start the local Function App:
   ```bash
   func start
   ```

6. Open your browser and navigate to `http://localhost:7071/api/dashboard`.
